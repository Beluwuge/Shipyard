# SHIP-001: Codex integration proof and decision record

Ticket: [SHIP-001 / issue #2](https://github.com/Beluwuge/Shipyard/issues/2). The owner's request to implement this ticket approves its proposed criteria. This bounded harness establishes observed integration behavior; it is not the production supervisor or backend.

Scope update: the owner requested local-first implementation before SSH deployment. Local review can proceed with explicitly labeled evidence from the existing account; the dedicated non-admin/remote acceptance criterion remains a later deployment verification rather than being reported as passed here.

## Pinned environment and integration decision

- Codex CLI: **0.148.0**, required exactly by the scripts. Node: **26.8.1 tested**, with Node 22+ built-ins and no third-party dependencies. Host: macOS.
- Use app-server JSON lines over stdio, owned by the future target supervisor. Start with initialize/initialized, then thread/start; persist the thread ID and use thread/resume after process restart.
- Package workflow as a filesystem skill plus MCP tool contract. This proof installs it only in a disposable repository's .agents/skills/workflow directory and supplies an explicit skill input item. Production plugin distribution is deferred.
- Preserve target-local login through the existing Codex executable and account. The harness never reads/copies token stores or implements an OAuth flow. Token renewal/attestation support is outside this proof.
- Keep owner criteria approval independent of tool approval. The MCP fixture accepts only unapproved drafts; it never launches jobs.

The request-only schema subset in [protocol/requests.json](../packages/codex-proof/protocol/requests.json) is generated by this exact binary, with reachable definitions preserved. Its [manifest](../packages/codex-proof/protocol/manifest.json) pins methods and SHA-256. It is a wire reference, not a claim of runtime JSON Schema validation or a snapshot of every upstream method. Synthetic transport tests and live evidence serve different purposes.

Official references: [app-server](https://learn.chatgpt.com/docs/app-server), [building skills](https://learn.chatgpt.com/docs/build-skills). Generated schemas and observed behavior are authoritative for this pinned proof when newer documentation differs.

## Run the proof

Prerequisites: provision a dedicated non-admin Linux/macOS account, independently verify its privilege delegation, authenticate Codex locally under that account, install Codex 0.148.0, and use a disposable environment. The script rejects obvious administrator group memberships and root; this group screen is not a complete audit of sudo rules or other delegated privileges.

From the repository root:

```sh
npm test
npm run proof:schema -- --check
npm run proof:metadata
python3 /path/to/skill-creator/scripts/quick_validate.py packages/workflow/skills/workflow
npm run proof:codex
```

The full mode sends a harmless command probe to Codex and automatically accepts single command/file requests scoped to its one proof thread. Broader permission requests, general elicitation, token refresh and attestation fail closed. Never reuse this test policy as a production authorization engine. The script uses a bounded workspace sandbox; broad OS-permitted filesystem access for the eventual product remains a separate deployment choice.

This proof sets approvalsReviewer to user and implements the single-action callback itself. Native approvalsReviewer=auto_review is present in the pinned schema but has not been demonstrated here; callback acceptance must not be described as a successful run of that native reviewer.

For a local protocol diagnostic on an administrator account:

```sh
npm run proof:codex -- --diagnostic
```

Diagnostic mode refuses command/file approvals and instructs Codex to use only text responses and the known mock draft tool. It may approve the exact known mock's draft-form elicitation for the proof thread; it rejects arbitrary forms and secrets. This mode cannot satisfy non-admin command execution or file-approval acceptance.

For the owner-authorized local execution phase, use:

```sh
npm run proof:codex -- --local --model gpt-5.6-sol
```

Local mode retains a read-only Codex sandbox under the current non-root account. Its approval callback permits only the literal harmless stdout probe (including known shell wrappers), with no permission or network overlays. It rejects file-change approvals and other commands. It also performs a non-mutating write-access check against the protected OS account directory. Local mode is labeled local-proof-only even if all checks pass; membership in the admin group is recorded rather than hidden. The default full proof continues to reject that account. Diagnostic and local modes are mutually exclusive, and all modes reject root.

The [local-first execution evidence](evidence/SHIP-001-local-proof.json) passes all 14 checks, with one observed command approval and one approved mock draft. The literal command completed with exit code zero and the expected marker. The protected-directory access check denied writes without attempting a modification. Eleven automated protocol/contract checks pass, including rejection of command suffixes, sudo prefixes, other commands, file approvals and permission/network overlays.

The local configured default was gpt-6-luna with high effort, while model/list exposed gpt-5.6-sol, gpt-5.6-terra and gpt-5.6-luna. Actual default-model turns failed with unsupported-model responses. The explicit follow-up diagnostic used:

```sh
npm run proof:codex -- --diagnostic --model gpt-5.6-sol
```

No automatic fallback occurs. An unavailable configured default is a visible compatibility failure. The production adapter must expose model availability errors and permit an owner-selected override rather than treating a catalog as an entitlement guarantee.

## Evidence and interpretation

Live artifacts are private-by-default files under ignored .shipyard-proof/: report.json contains explicit status/metadata fields; session.json contains the actual thread ID and disposable repository path. Restart/resume reads the persisted checkpoint. Raw stderr is drained; raw protocol/conversation content is retained only in process memory and is never copied into report.json. The pinned CLI can still maintain its own native local session history.

The script creates a temporary Git repository, installs the repository skill there, and configures the known mock MCP server. Source credentials remain in their original account store. The disposable workspace is retained to permit inspection; session.json identifies it. To remove it, first confirm no proof process remains and delete only that recorded temporary directory. Do not copy session.json into public evidence.

Published evidence is an explicitly selected sanitized copy, not automatic log uploading. [Default-model failure](evidence/SHIP-001-default-model-failure.json) preserves the original failed run. The [explicit-model diagnostic](evidence/SHIP-001-macos-diagnostic.json) passed all 12 local checks with one skill invocation attempt. The [observed wire metadata](evidence/SHIP-001-wire-metadata.json) records frame shapes and field names, excluding payload values; it is not a raw replay transcript. Each report's overall status must be read: diagnostic-only does not mean the ticket passed on a non-admin target.

Live checks cover handshake rejection before initialization, a real inference turn, stream notifications, process restart and same-thread continuation, repository skill discovery/explicit invocation, mock draft creation and its returned URL, model/effort overrides, invalid model failure, and interruption reconciliation. Unit tests exercise response correlation, early notifications, process exit, timeouts, approval scoping, mock request validation/idempotency, and pinned-schema reference integrity.

## Observed edge cases and alternatives

1. Codex's tool-call approval for this MCP fixture arrived as mcpServer/elicitation/request with form mode and metadata, not as a command approval. The proof handles only the known server/thread, empty form and fixture draft arguments. General elicitation is unsupported and cannot be auto-accepted by analogy.
2. An interrupt sent immediately after turn/start was rejected because the turn was not yet active. Closing the process later marked its history interrupted; that is not evidence of a successful interrupt request. The corrected probe waits for an inference delta, then interrupts. In the final diagnostic both the acknowledgement and terminal event were observed. If a terminal event is absent, query thread/read for the exact turn before shutdown and require its stored status to be interrupted. Never interpret a timeout as proof of cancellation.
3. Process exit may leave inherited stream descriptors open. The client tears down its streams explicitly after bounded child shutdown. This client is not the durable process-tree supervisor required by SHIP-006.
4. This machine's account belongs to admin. Text/MCP diagnostics are useful here, but OS-boundary and live command/file approval behavior must be demonstrated using the intended non-admin target before SHIP-001 is accepted.
5. MCP readiness is checked explicitly before invoking the skill. If a completed model answer produces no mock receipt, the harness permits one explicit correction with the same request key and records the extra attempt. It never retries a turn whose outcome is uncertain. Earlier exploratory diagnostics demonstrated this model-dependent failure, so production code must validate tool outcomes instead of trusting generated claims.

The command probe requires both an observed automatic approval and a completed command item with exit code zero and the expected harmless marker. It also checks that a protected OS directory is not writable using an access check without modifying it. These checks now pass in the constrained local mode. The dedicated-account deployment path remains unverified; the owner deferred SSH execution to a later stage. No target credentials or account details are published in these evidence files.
